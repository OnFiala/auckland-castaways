# Offline release check

The **Game release QA** workflow builds the distribution with `python adventure/tools/build_web.py <empty-absolute-directory>`, packages it with `adventure/tools/package_download.py`, verifies the unpacked hashes with `adventure/tools/verify_web.py`, and opens the unpacked root `index.html` in clean offline Chromium profiles. With Python 3.12, Pillow 11.3.0, Playwright 1.56.0 and its Chromium installation, run `python adventure/tests/browser/release_qa.py <unpacked-directory>/index.html <evidence-directory>`. Two ordinary-motion shore visits measure Alick’s leftward gait to the rope and pull the painted wreck block by mouse and touch. A separate reduced-motion campaign plays all seven chapters, including closing and reopening Epigwaitt’s survey and filing the epilogue’s witness accounts and dates, and a disposable copy exercises staying in the current room and retrying a missing painting. The workflow retains the tested ZIP, videos, screenshots, hit coordinates, movement samples and the release number. No server, account, source-game save or credentials are needed.

If the campaign fails, a separate fresh game records overlapping room and workbench controls in `diagnostic/blocked-centres.json`. It uses Tab and Enter on those controls so later chapters can still be tested. The original failure keeps the release check red.
